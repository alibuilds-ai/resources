GLM 5.3 Flash on OpenRouter, driven by Hermes Agent

Half an hour of setup for a coding model that reads 1.3M tokens and bills at a fraction of what a frontier subscription costs. Here is the model id, what it actually charges, the Hermes config that points at it, and the part of your setup that should not change when you swap the model out again.

The stealth model from sheet 02 has a name now. Ox Alpha was GLM 5.3 Flash, from Z.ai, released on 26 August 2026 with the weights published on Hugging Face under MIT. The tokenizer match people spotted during the stealth window was the right read.

Two things make it worth wiring up rather than just trying in a playground. It takes 1,310,720 tokens of context, which is more than any agent loop you are likely to write will fill. And it is priced low enough that the per-token cost stops being the thing you plan around.

For comparison, Claude Opus 5 is $5 per million in and $25 per million out. At list price that is a 33x gap on input and 50x on output. On the promo it is closer to 66x and 100x. Those ratios are the reason this sheet exists, but they are also the reason to keep reading past them: cheap tokens change what you can afford to run, not what the model is good at.

Setup

  1. Get an OpenRouter key

    Make one at openrouter.ai/keys. Load a few dollars of credit. At these prices a few dollars is a lot of agent runs, and it also lifts you off the free-tier request caps.

    Confirm the model answers before installing anything on top of it:

    curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"z-ai/glm-5.3-flash",
       "messages":[{"role":"user","content":"say ok"}]}'

    Any OpenAI SDK works with the same two values: base URL https://openrouter.ai/api/v1, model z-ai/glm-5.3-flash. If all you wanted was a cheaper model behind code you already wrote, you are finished here.

  2. Install Hermes Agent

    curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

    Linux, macOS, WSL2 and Termux. Windows PowerShell support is early beta, so on Windows use WSL2. Hermes is MIT licensed and runs the same agent from a terminal or from Telegram, Discord, Slack, WhatsApp, Signal and email, which is the main reason to pick it over a terminal-only agent.

  3. Point it at GLM

    Fastest path, no file editing:

    hermes config set OPENROUTER_API_KEY sk-or-...
hermes chat --provider openrouter --model z-ai/glm-5.3-flash

    Or run hermes model and pick from the interactive list, which writes the choice to ~/.hermes/config.yaml for you. The manual equivalent, key in ~/.hermes/.env and the rest in config.yaml:

    # ~/.hermes/.env
OPENROUTER_API_KEY=sk-or-...

# ~/.hermes/config.yaml
model:
  provider: openrouter
  default: z-ai/glm-5.3-flash

    Hermes docs show two shapes for this key, a mapping as above and a flat string such as model: openrouter/z-ai/glm-5.3-flash. Run hermes config view after setting it and use whichever shape your build echoes back. Secrets belong in .env, everything else in config.yaml, and CLI flags beat both.

    Hermes asks for at least 64K of context because the system prompt and tool schemas eat a large slice before your first message. GLM 5.3 Flash has twenty times that, so this constraint stops mattering.

  4. Control which provider serves you

    Twenty-one providers serve z-ai/glm-5.3-flash on OpenRouter, and they are not equally fast. Provider routing passes your preference through to OpenRouter on every request:

    # ~/.hermes/config.yaml
provider_routing:
  sort: throughput        # or: price, latency
  only: []
  ignore: []
  order: []
  require_parameters: true
  data_collection: deny

    require_parameters: true drops providers that quietly ignore tools or temperature, which is the failure that looks like the model being stupid rather than the route being wrong. data_collection: deny keeps your prompts off providers that train on them. Both are worth setting before you notice you needed them. This block only does anything on OpenRouter or Nous Portal.

  5. Give it somewhere to fall back to

    A single cheap provider will be down at some point. Chain a second one, and push the small background calls onto something cheaper still:

    # ~/.hermes/config.yaml
fallback_providers:
  - provider: openrouter
    model: z-ai/glm-5.3-flash
  - provider: openrouter
    model: ~google/gemini-flash-latest

auxiliary:
  compression:
    provider: openrouter
    model: ~google/gemini-flash-latest
  title:
    provider: openrouter
    model: ~google/gemini-flash-latest

    The ~ prefix in the OpenRouter docs marks a floating alias that tracks the newest version of a model. Use the bare slug when you want a pinned model that cannot change under you, which is what z-ai/glm-5.3-flash is.

    Conversation compression is on by default and summarises the history once it passes half the context limit. With a 1.3M window you will rarely reach it, so if you want it never to fire, raise compression.threshold rather than turning the feature off.

  6. Sandbox it before you let it run commands

    Hermes runs shell commands on your machine by default. A cheap model that is willing to try things is a good reason to put a wall around it:

    # ~/.hermes/config.yaml
terminal:
  backend: docker
  docker_image: nikolaik/python-nodejs:python3.11-nodejs20
  docker_mount_cwd_to_workspace: true
  container_persistent: true

    ssh, modal, daytona, vercel_sandbox and singularity are the other backends if Docker is not where you want it running.

what you are actually buying

Z.ai's own benchmarks put GLM 5.3 Flash level with Opus 4.8 on coding and agent work, and a community DeepSWE run had it above Claude Fable 5. Vendor benchmarks and ten-task community runs are both weak evidence. What is not in dispute is the price and the context window. Treat the quality claim as something to test on one real task from your own repo, not something to plan a migration around.

The part that decides whether the next swap is cheap

Everything above is the easy half. Changing model takes two lines. What makes migrations expensive is that most people's agent setup is glued to one tool: instructions live in a CLAUDE.md that only Claude Code reads, decisions live in a chat history that does not export, and the workflow lives in a framework's Python.

Jake Van Clief and David McDermott published the fix in March 2026 as the Interpretable Context Methodology, and the Model Workspace Protocol underneath it. The idea is short: put the orchestration in the filesystem. Numbered folders are the stages. Plain markdown files carry the role and the context for each stage. Local scripts do the mechanical work that does not need a model. One agent walks the folders in order.

workspace/
├── IDENTITY.md              where am I, what is this workspace
├── CONTEXT.md               where do I go, what happens next
├── stages/
│   ├── 01_research/
│   │   ├── CONTEXT.md       the role and rules for this stage
│   │   ├── references/      source material the stage may read
│   │   └── output/          the handoff to stage 02
│   ├── 02_script/
│   │   ├── CONTEXT.md
│   │   ├── references/
│   │   └── output/
│   └── 03_production/
│       ├── CONTEXT.md
│       ├── references/
│       └── output/
└── _config/
    ├── conventions.md
    ├── glossary.md
    └── voice.md

The paper's claim about portability is explicit: "ICM is designed to be model-agnostic. The protocol specifies folder structure, file formats, and naming conventions. It does not depend on any model-specific capability." Nothing in that tree is a Claude feature, an OpenAI feature or a framework API. It is numbered directories and markdown. Point GLM at it and it reads the same files Claude read.

Tool-specific instruction files become adapters rather than the source of truth. IDENTITY.md holds the real content, and CLAUDE.md, .cursorrules or .github/copilot-instructions.md are thin files pointing at it. The icm-template repo is MIT and ships Claude Code skills that scaffold the tree for you, but the structure is the deliverable and you can create it with mkdir.

the honest caveat

The model-agnostic claim is a design claim, not a measured one. The authors tested on Claude Opus 4.6 and Sonnet 4.6 only, and say so: "all current testing has been conducted on a single model family. Cross-model evaluation is a clear next step." The reported evidence is practitioner feedback from 33 people, not a controlled comparison. So build the folders because plain files survive tool churn and you can read them yourself, not because a paper proved a number.

if you copy one thing

Move your project instructions out of the tool-specific file and into a plain markdown tree this week, while you are still on Claude. Do that first and the model swap is a config edit. Do it after and the swap is a rewrite, which is exactly the cost that keeps people paying for a subscription they have stopped enjoying.
