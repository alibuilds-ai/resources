Run Qwen3.8-27B on one 24GB GPU

A 27B vision model with a 256K window, Apache 2.0, that fits in about 17GB once Unsloth has quantised it. Here is which file to download, the one command that turns it into an OpenAI endpoint, the sampler settings it needs, and what you give up by running it at home.

Qwen3.8-27B is Alibaba's dense 27B release from 14 August 2026, Apache 2.0, with vision and hybrid reasoning and a 256K native context that stretches to 1M with YaRN. At full BF16 precision it wants about 56GB, which is two expensive cards. The reason it is on this sheet is Unsloth, whose Dynamic v3 quants get it down to roughly 17GB with most of the quality intact.

The rule of thumb for what fits where:

PieceWhat to useSource
WeightsApache 2.0, 27.78B dense, visionQwen/Qwen3.8-27B
QuantsUD-Q4_K_XL for 24GB cardsunsloth/Qwen3.8-27B-GGUF
Smallest1-bit, ~8GB, keeps about 77% accuracyUnsloth docs
FastestNVFP4, 1.5x BF16 speed, 92–97% top-1same repo, NVFP4 files
Runtimellama-server, OpenAI-compatibleggml-org/llama.cpp
GUI optionsUnsloth Desktop, LM Studio, Ollamalmstudio.ai · ollama.com

Setup

  1. Download the quant that fits

    pip install -U "huggingface_hub[cli]"
hf download unsloth/Qwen3.8-27B-GGUF \
    --local-dir unsloth/Qwen3.8-27B-GGUF \
    --include "*UD-Q4_K_XL*"

    The UD prefix is what you are here for. Unsloth's Dynamic quants vary the precision per layer instead of flattening everything to the same bit width, and their v3 release claims about 10% better accuracy than a plain quant of the same size. Drop to UD-Q3_K_XL if 19GB is tight, and only go to the 1-bit file if the alternative is not running it at all.

  2. Serve it as an OpenAI endpoint

    One command, and everything else in your stack can talk to it:

    llama-server -hf unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_XL \
    -ngl 999 -fa on -c 65536 --port 8080

    That serves http://127.0.0.1:8080/v1. -ngl 999 puts every layer it can on the GPU, -fa on turns on flash attention, and -c 65536 sets the context. Start at 64K rather than the full 256K: context is the part that pushes you over the card, and you can raise it once you know how much headroom the weights left you.

    To check the model before wiring anything to it, llama-cli with the same file gives you a prompt in the terminal.

  3. Set the sampler correctly

    This is the step people skip, and then conclude the model is bad. Qwen3.8 wants different settings depending on whether it is thinking:

    SettingThinkingInstruct
    temperature1.00.7
    top-p0.950.80
    top-k2020
    min-p0.00.0
    presence penalty0.01.5
     
    llama-cli --model unsloth/Qwen3.8-27B-GGUF/Qwen3.8-27B-UD-Q4_K_XL.gguf \
    --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0

    The presence penalty on the instruct side is there to stop repetition loops. Reasoning effort is adjustable at three levels, and low effort on a routine edit saves you a lot of tokens you were going to read past anyway.

  4. Or skip llama.cpp entirely

    Unsloth Desktop is a GUI for macOS, Windows and Linux that picks parameters, finds your GPUs and offloads to RAM when the model does not fit. LM Studio does the same job with its own model browser.

    Ollama takes an extra step, because these Unsloth quants are not in its library. Point a Modelfile at the file you downloaded and import it:

    printf 'FROM ./Qwen3.8-27B-UD-Q4_K_XL.gguf\n' > Modelfile
ollama create qwen3.8-27b -f Modelfile
ollama run qwen3.8-27b

    Include the vision projector file from the same Hugging Face repo if you want it to read images, otherwise you have imported a text-only model and lost half of what makes this release interesting.

  5. Put an agent on it

    A local endpoint is only useful once something drives it. Hermes Agent treats a local server as a normal provider:

    # ~/.hermes/config.yaml
model:
  default: qwen3.8-27b
  provider: custom
  base_url: http://localhost:8080/v1
  api_key:
  context_length: 65536

    Or run hermes model and choose the custom endpoint option, which asks for the same three values. Leave the key empty for a local server. If you keep both a cloud model and this one, name them and switch mid-session:

    providers:
  local:
    api: http://localhost:8080/v1

model:
  provider: custom:local
  default: qwen3.8-27b

    Then /model custom:local:qwen3.8-27b in a session moves the work onto your own hardware without restarting anything. vLLM, SGLang and Ollama are supported the same way, so the endpoint you built in step 2 is not a commitment either.

what running it locally actually costs

Electricity instead of tokens, and a real quality gap on hard planning work. A quantised 27B is not a frontier model and no amount of setup makes it one. What it is good at is the routine 80%: renames, test scaffolds, reading a long file and answering questions about it, anything you would rather not meter. It also runs with no network, which matters for code you are not allowed to send anywhere. The published accuracy retention figures come from Unsloth's own benchmarks, so treat them the way you would treat any vendor's numbers.

Fine-tuning, which is what Unsloth is actually for

The GGUFs are a side product. Unsloth exists to make fine-tuning fit on one consumer GPU, and a 27B with a small LoRA on your own codebase or writing is within reach of the same 24GB card. That is the version of "local model" that a hosted API cannot sell you, because the thing you are adding is your own data. The training recipes are in the model docs alongside the inference instructions.

Keep the workspace, swap the model

This model and the hosted one on sheet 06 only stay interchangeable if your project instructions are not welded to one tool. The structure that makes that true is Jake Van Clief and David McDermott's Interpretable Context Methodology: numbered stage folders, a CONTEXT.md per stage carrying the role, references/ in and output/ out, and an IDENTITY.md at the root that any model can read to work out where it is.

Nothing in that tree is a capability of any particular model, which is the point. The same folders that a frontier model walked this morning are the folders this 27B walks tonight, and the only thing that changed is four lines of config.yaml. The full layout and the caveats on the paper's evidence are on sheet 06.

if you copy one thing

Run step 2 tonight and leave the server running for a week. Send it the boring work, keep the hard problems on whatever you are paying for, and see what fraction actually comes back local. That number is your real answer about cancelling anything, and it is different for everybody.
