Five free plugins your Claude Code setup is missing

Each one takes a specific limit out of your setup: the usage wall, the hour you spend picking skills, the config nobody audits, the vulnerability you ship, the site that blocked its API. Repo, install command and the catch for all five.

These are five separate projects, four of them from outside Anthropic, and they solve five unrelated problems. What ties them together is that none of them changes how you write prompts. They change what sits around Claude Code: the gateway in front of it, the skills inside it, the config underneath it, the scan after it, the internet beside it.

Everything below is free and open source, with the licence and the star count as of 27 August 2026. Star counts move; the commands do not.

Installing each one

  1. OmniRoute: the usage wall

    A local gateway that speaks the OpenAI API and sits between your CLI and every provider it knows about. Install it and it boots on localhost:20128 with no key and no signup, because a couple of keyless free providers are pre-wired into the default combo.

    npm i -g omniroute
omniroute                       # gateway + dashboard on :20128

curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'

    Point any OpenAI-compatible tool at http://localhost:20128/v1: Claude Code, Codex, Cursor, Cline, OpenCode, Copilot. The repo claims 350 providers, 90+ of them free, and 1,200+ models. The part that matters day to day is the cascade: it routes across four tiers (your subscription, then your API keys, then cheap, then free) and falls through to the next healthy target when one runs out, so a quota that empties mid-session does not end the session.

    It also exposes itself over MCP if you would rather the agent drive the gateway than read a config file:

    claude mcp add-server omniroute --type http \
  --url http://localhost:20128/api/mcp/stream

  2. Skills CLI: picking skills by hand

    Skills are packaged expertise an agent loads on demand, and the ecosystem is now large enough that browsing it manually is the slow path. The CLI searches it from a description of the job:

    npx skills find "scrape a site with no api"
npx skills add agent-reach
npx skills check                # what has updates
npx skills update

    The find-skills skill wraps the same CLI so the agent runs the search itself when you describe a task it has no skill for. Browse the registry at skills.sh if you want to see what exists before installing anything.

  3. Claude Code Setup: the config nobody audits

    Anthropic's own plugin, from the official marketplace. It reads the codebase and recommends the top one or two automations per category: MCP servers, skills, hooks, subagents, slash commands.

    /plugin install claude-code-setup@claude-plugins-official

    Then ask it in plain language: recommend automations for this project, or what hooks should I use. Read the output as a proposal, not a migration. The skill is read-only by design and will not touch your files, so adding or removing anything is still your keystroke.

  4. Strix: the vulnerability you were about to ship

    An agent that attacks a running app the way an attacker would, then reports what it found with a working proof of concept rather than a severity label. Needs Docker running and an LLM key from any supported provider.

    curl -sSL https://strix.ai/install | bash

export STRIX_LLM="openai/gpt-5.4"
export LLM_API_KEY="your-api-key"

strix --target ./app-directory

    First run pulls the sandbox image, and results land in strix_runs/<run-name>. It takes a repo and a live URL in the same command (strix -t https://github.com/org/app -t https://your-app.com), which is the mode worth using: source plus running instance beats either alone.

  5. Agent Reach: the platforms that closed their API

    One CLI that reads and searches across 13 platforms (Twitter/X, Reddit, YouTube, GitHub, LinkedIn, Bilibili, XiaoHongShu and more), routing each one to whichever backend currently works, with no per-platform API bill. Six channels need no key at all.

    agent-reach doctor --json       # which backend serves each platform

    Installation runs through the agent: point it at docs/install.md in the repo and let it do the environment checks. By default agent-reach install only inspects your environment and writes nothing; it needs --system before it will install system packages. Run doctor first, always. It tells you which platforms are live for you right now instead of failing halfway through a research run.

the honest catch

Free routing is not free capability. OmniRoute's free tier is a pool of other people's free tiers, which means variable latency, variable model quality and providers that disappear. Keep the model id in one config value and treat the free lane as a fallback for grunt work, not as the thing your paid work depends on.

before you point Strix at anything

Only scan what you own or have written permission to test. Strix drives a real attack against a real target, and pointing it at someone else's app is not a grey area.

If you install one

Take OmniRoute if you hit the wall most afternoons, Strix if you ship anything with a login. Those two change what you can do. The other three change how long it takes you to do it, which matters, but only once the first two are handled.
